# TomeForge UX Decision Log

## 2026-06-20 — Session 1: Update → Finalize

This log was created during the UX Update/Finalize session. Previous decisions are now captured as entries.

### UX-1: Visual Identity — Modern TCG Aesthetic
- **Decision:** Dark slate UI panels with violet accents framing crisp white cards
- **Rationale:** TCG presentation language reduces eye strain, keeps card center-stage
- **Status:** captured

### UX-2: Layout — 3-Column Coordinated Panels
- **Decision:** Left panel (260px deck navigation) | Center (flex, context-aware content) | Right panel (384px editor/settings)
- **Rationale:** Clean separation between navigation, content, and editing
- **Status:** captured

### UX-3: View Model — Deck View + Card View
- **Decision:** Two primary editor states switching on selection
- **Deck View:** Center = card grid gallery, Right = deck settings
- **Card View:** Center = single card preview, Right = card editor
- **Rationale:** Prevents settings clutter, keeps editing focused
- **Status:** captured

### UX-4: Card Format — Poker + Tarot
- **Decision:** Two print sizes at MVP
- **Poker:** 2.5" × 3.5" (63mm × 88mm)
- **Tarot:** 2.75" × 4.75" (70mm × 121mm)
- **Rationale:** Spells fit Poker; cards with more text need Tarot
- **Status:** captured

### UX-5: Auto-save Strategy
- **Decision:** Local storage auto-save within 500ms of any field change
- **Rationale:** No explicit save button reduces friction; single-user no sync conflicts
- **Status:** captured

### UX-6: Typography Direction
- **Decision:** Inter for UI, Inter for card text. No fantasy UI fonts.
- **Rationale:** Clean modern UI, card content reads as print-ready
- **Status:** captured

### UX-7: Future Surface — Mobile
- **Decision:** Deferred. Desktop-first with tablet responsive breakpoints.
- **Rationale:** Primary use case is desk-based D&D prep
- **Status:** captured, deferred
